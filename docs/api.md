# API reference (C++)

Header `src/ignition_zero.hpp`, namespace `ignition_zero`.

```cpp
struct Params {
    double A;      // pre-exponential factor [1/s]
    double Ea;     // activation energy [J/mol]
    double R;      // gas constant, same molar basis as Ea [J/(mol K)]
    double q;      // heat release per fuel mass [J/kg]
    double cp;     // specific heat [J/(kg K)]
    double T0;     // initial temperature [K]
    double Y0;     // initial fuel mass fraction [-]
    double dt;     // step [s]
    int n_steps;   // number of steps
};
```

- `integrate_adiabatic(p, t_out, Y_out, T_out, len)` — fixed-step RK4;
  every intermediate stage and the final state must be finite, physical
  (Y ≥ 0, T > 0), and monotone (Y non-increasing, T non-decreasing in the
  adiabatic mode) — unstable steps are rejected, never clipped.
- `integrate_isothermal(p, T_fixed, t_out, Y_out, len)` — thermostatted
  benchmark; no energy conservation claimed in this mode. The same stage
  checks apply: an oversized dt·k that would make RK4 *grow* Y (e.g.
  Y_new ≈ 291·Y_old at dt·k = 10) is rejected with error 2.
- `integrate_quench_safe(p, t_out, Y_out, T_out, len)` — RK4 with
  positivity/monotonicity step-halving retry (NOT adaptive error control;
  no truncation-error estimate exists). Exactly `n_steps` accepted steps
  are taken; `t_out` records the ACTUAL accumulated times after any
  halving — use those, not (i+1)·dt, for every comparison and plot.

**Error codes** (all functions): 0 OK; 1 invalid input (non-finite or
out-of-domain parameters, including ±∞ and NaN; non-finite or non-positive
`T_fixed`); 2 a step or stage left the physical domain (reduce dt); 3
non-finite state; 4 output buffer too small.

**Output-buffer contract**: either all history pointers are null (final
state only — nothing recorded), or `len` must be ≥ `n_steps`; a non-null
history array with insufficient capacity is rejected with error 4 instead
of silently truncating the requested integration.

## Build (portable: CMake + CTest)

```bash
cmake -S . -B build
cmake --build build --config Release --parallel
ctest --test-dir build -C Release --output-on-failure
```

The CTest suite is the CI gate (Ubuntu + Windows matrices). The demo
binary `ignition_demo` writes `build/ignition_history.csv`; results
figures are regenerated by `python examples/run_verification.py`, which
builds and runs the C++ demo and plots its CSV output.
